核心战果：Top-1 跃升 25.1 个百分点，突破 85% 大关；Top-3/Top-5 均突破 92%。路由错判率降低 56.5%，系统对真实口语化变体的承载力产生质的飞跃。

🧠 二、 为什么重构能“药到病除”？（三大底层变革）
之前的架构陷入了“打地鼠”的被动循环，是因为试图用向量空间区分结构高度相似的句子（如计数类法规问 vs 统计问）。本次重构通过“承认冲突、降维拦截、合并容错”彻底扭转了局势：

1. 从“互斥二选一”走向“跨库联合精排”
旧痛点：非 SQL 问题被强行路由到 regulations（法规）或 bids（招标）单一库。一旦路由判错，哪怕检索模型再强，也彻底断送了找到正确答案的可能。

新解法：全面解耦非 SQL 路径。允许提问同时穿透 regulations + bids 两个物理库，利用混合检索（BM25 + ChromaDB）全量召回，最后交由 bge-reranker-base 站在全局视角跨库精排。彻底消除了“问法规被塞进招标项目名”的路径窒息。

2. 路由目标降维：三分类变二分类网关
旧痛点：试图让大模型或 Embedding 强行在高维空间区分“评标委员会最少几个人”和“一共有多少条数据”，语义高度纠缠。

新解法：路由不再承担复杂的意图拆解，只做单任务网关——“要不要写 SQL 计算？”。通过“统计/排名/总共”等聚合词，配合“应当/必须/不得”等法理阻断词建立确定性边界，使 SQL 网关准确率直飚 90%。

3. 引入工业级 Fallback（容错降级）闭环机制
旧痛点：路由是单向玻璃，撞碎即报错。

新解法：系统架构具备了自愈能力。本次测试中，有 10 条法规问题被误判误入 SQL 路径。但由于系统引入了 try-except 容错机制，在 SQL 算不出数据或执行异常时，自动触发降级，无缝转入混合检索。最终结果证实：没有一条数据因为路由误判而断送答案
