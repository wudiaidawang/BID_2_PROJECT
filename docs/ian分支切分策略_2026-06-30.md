# ian 分支切分策略

**来源**: `origin/ian` @ `31689f0`
**日期**: 2026-06-30
**对比基线**: V4.2 (child chunk 全废除)

---

## 一、数据源总览

```
init_policy_collection.py
├── policy_data.xlsx     → policy_doc      (政策法规 Markdown)
├── opinion_data.xlsx    → opinion_news    (舆情/解读)
└── 10个 PDF
    ├── law_article  ×4  → pdf_law_parent + pdf_law_child  (法条结构化)
    ├── paragraph    ×1  → pdf_case_paragraph               (案例段落归并)
    └── sliding      ×5  → pdf_case_sliding                 (案例滑动窗口)
```

## 二、6种 chunk_type

| chunk_type | 来源 | 切分方式 | 预计数量 |
|---|---|---|---|
| `policy_doc` | policy_data.xlsx | 单条=单chunk（header注入） | ~1100 |
| `opinion_news` | opinion_data.xlsx | 单条=单chunk（header注入） | ~266 |
| `pdf_law_parent` | 法条PDF ×4 | 每条法条=1个parent | N |
| `pdf_law_child` | 法条PDF ×4 | 长法条拆分出的child | M（≥0） |
| `pdf_case_paragraph` | 解读PDF ×1 | 段落归并（~500字/块） | ~669 |
| `pdf_case_sliding` | 案例PDF ×5 | 滑动窗口（500字/200重叠） | ~252 |

## 三、核心：Parent-Child 拆分（law_article 模式）

### 3.1 配置参数

```yaml
legal_chunking:
  parent_context_enabled: true
  child_split_threshold: 400      # 超过400字才拆分
  child_target_size: 300          # child目标大小
  child_overlap: 40               # 跨child重叠字符数
  header_injection_enabled: true
```

### 3.2 流程

```
LawDocument (LegalStructureParser 输出)
  │
  ▼
ParentChunkBuilder.build()
  ├── 每条法条 → 1个 parent chunk
  ├── retrieval_text = header + 正文 (参与向量化/BM25)
  ├── text = 纯正文 (用户展示)
  ├── header 区分长短:
  │   ├── 正文 < 200字: 紧凑header "《招标投标法》/ 第一章 总则 / 第一条"
  │   └── 正文 ≥ 200字: 完整header "《中华人民共和国招标投标法》\n第一章 总则\n第一条"
  │
  └── 元数据: source_doc, law_name, chapter, article, article_id, chunk_type
        │
        ▼
ChildChunkBuilder.build_all(parents)
  │
  ├── 短法条 (raw_content ≤ 400字):
  │   → parent 自身成为 searchable_parents，不产生 child
  │
  └── 长法条 (raw_content > 400字):
      → 按优先级尝试拆分:
         ① _split_by_subsections: 正则 (一)(二)(三) 子项边界
         ② _split_by_paragraphs: \n\n 自然段边界
         ③ _split_by_sentences: 。；！？ 句子边界 + 40字 overlap
      → 拆分失败则降级: parent 自身参与检索
      → 拆分成功: 每段生成一个 child chunk
         每个 child 继承 parent 的 header 注入到 retrieval_text
         parent 本身不参与检索
```

### 3.3 关键差异：ian vs V4.2

| | V4.2 (当前生产) | ian 分支 |
|---|---|---|
| Child Chunk | **废除** — build_all() return ([], []) | **恢复** — 长法条拆分 |
| 短法条 | 所有 parent 都参与检索 | ≤400字 parent 参与检索 |
| 长法条 | 完整法条直接检索 | 拆成 children，parent 不参与 |
| chapter_context | 无（parent_chunk_builder 无此方法） | 无（同样没有） |
| 检索单元数量 | 较少 | 更多（多了 child chunks） |

## 四、非结构化 PDF 切分

### 4.1 段落归并 (paragraph 模式)

```
PDF全文 → \n\n 分自然段 → 过滤短段(<50字) → 相邻段归并至~500字
→ retrieval_text = 《pdf_name》\n{chunk}
→ chunk_type: pdf_case_paragraph
```

用于：`招标投标法律解读与风险防范实务.pdf`

### 4.2 滑动窗口 (sliding 模式)

```
chunk_size=500, overlap=200
在 。\n；！？ 处尽量对齐语义边界
→ retrieval_text = 《pdf_name》\n{chunk}
→ chunk_type: pdf_case_sliding
```

用于：5个案例类PDF

### 4.3 兜底：law_article 解析失败时

```
结构化解析 → 附录过滤 → 若 article_count=0 → 回退滑动窗口
→ chunk_type: pdf_law_sliding
```

## 五、质量过滤

| 数据源 | 过滤规则 | 影响 |
|---|---|---|
| policy_data.xlsx | 正文摘要 < 100字 → 跳过 | 过滤页脚、版权声明 |
| opinion_data.xlsx | 标题 < 5字 → 跳过 | 过滤无意义行 |
| 法条PDF | 附录/模板检测器移除空白附件 | 过滤表单、附录页 |

## 六、Header 注入规则

| chunk_type | retrieval_text 格式 |
|---|---|
| `pdf_law_parent` | `{compact/full header}\n{正文}` |
| `pdf_law_child` | `{父header}\n{子段内容}` |
| `pdf_law_sliding` | `《{pdf_name}》\n{chunk}` |
| `pdf_case_paragraph` | `《{pdf_name}》\n{chunk}` |
| `pdf_case_sliding` | `《{pdf_name}》\n{chunk}` |
| `policy_doc` | `【政策法规】《{title}》\n{publisher}\n{summary}` |
| `opinion_news` | `【招标公告】来源:{source}\n{title}\n关键词:{keywords}` |
