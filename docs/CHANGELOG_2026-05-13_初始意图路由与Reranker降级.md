1. 核心逻辑变更：意图路由拦截 (Intent Router)
为了解决“统计类问题回答不准”和“LLM 重写导致指令丢失”的问题，我们优化了路由器的触发机制。

修改点：在 api/routes.py 中，优先使用用户原始问题（Original Query）进行意图识别，随后再进行 LLM 问题重写。

鲁棒性提升：防止 LLM 在润色时将“一共”、“多少条”等硬性统计指令改写为模糊的文学表达，确保 SQL 引擎能够 100% 拦截统计需求。

匹配增强：在 router.py 中加入了 clean_query 逻辑，剔除标点符号干扰，并使用了更鲁棒的正则规则。

2. 性能与稳定性修复：Reranker 降级处理
针对之前出现的“请求超时”和“后端卡死”问题进行了深度修复。

修改点：在 retriever.py 中暂时禁用了 FlagReranker 的联网加载逻辑，将其 _get_model 强制设为 None。

原因：HuggingFace 镜像站 SSL 连接不稳会导致主线程在模型下载时死锁。

结果：响应耗时从 17s+ 降低至 2.6s。在本地网络环境受限时，系统会自动采用“向量检索 + BM25 关键词检索”的融合方案，确保服务高可用。

3. SQL 模式的数据对齐 (Data Marshalling)
数据包装：SQL 查出的统计结果（如 COUNT）会被包装成标准的 context 喂给 LLM。

LLM 引导：通过在上下文前缀加入“系统数据库实时统计结果”字样，强制 LLM 引用精确数据，彻底解决了 LLM 回复“无法确定数据条数”的问题。

4. 类型安全处理 (Type Safety)
金额转换：在 routes.py 的 Source 提取环节，加入了 try...except 浮点数转换逻辑。

防御逻辑：对于数据库中可能存在的空值（None）或脏数据（非法字符串），统一 fallback 到 0.0，防止接口返回 500 错误。
