# pdf_law_child 召回提升优化方案

基于诊断结果，针对法律条文检索中query与chunk表达差异大的问题，提出以下具体可落地的优化方案：

## 1. 增强查询理解与表达转换

**方案：构建法律领域查询重写与扩展系统**

**具体步骤：**
1. **构建法律术语同义词词典**
   - 收集法律领域常见口语表达与正式术语对应关系（如"招标人自行办理"→"招标人自行办理施工招标应具备的具体条件"）
   - 从现有420个测试案例中提取所有query与chunk的对应关系，构建至少500对同义表达映射
   - 建立定期更新机制，每季度扩充100对新的映射关系

2. **实施查询重写策略**
   - 对每个查询生成3个版本：原始查询、术语替换查询、扩展查询
   - 例如："招标人自行办理施工招标事宜需要什么条件？" → 
     - 原始查询：招标人自行办理施工招标事宜需要什么条件？
     - 术语替换：招标人自行办理施工招标应具备的具体条件
     - 扩展查询：招标人 自行办理 施工招标 条件 要求 资质

3. **实现多查询检索**
   - 修改检索流程，对每个原始查询同时检索3个版本
   - 合并3个版本的检索结果，去重后按RRF公式重新排序
   - 预期提升：双路都丢失的8%案例可减少3-4%

## 2. 优化BM25分词与匹配策略

**方案：法律领域专用分词与加权策略**

**具体步骤：**
1. **定制法律领域分词词典**
   - 收集法律专业术语、机构名称、法律条文编号等专有名词
   - 在jieba分词基础上添加至少1000个法律领域专有名词
   - 实现混合分词模式：对法律术语进行整体切分，普通文本按jieba分词

2. **实施关键词加权策略**
   - 识别查询中的法律专业术语、条件词、行为词等
   - 对不同类型关键词设置不同权重：
     - 法律专业术语权重×1.5
     - 条件词（如"需要"、"应当"、"情形"）权重×1.3
     - 行为词（如"办理"、"评审"、"停止"）权重×1.2
   - 修改BM25评分函数，融入上述权重机制

3. **实现短语匹配增强**
   - 对法律固定表述（如"自行办理施工招标事宜"、"停止评审活动"）进行短语匹配
   - 当查询包含短语时，优先返回包含完整短语的文档
   - 预期提升：BM25独有10%的案例中可召回5-7%

## 3. Dense检索模型优化

**方案：法律领域语义增强与负样本学习**

**具体步骤：**
1. **构建法律领域训练数据**
   - 从现有数据中筛选10,000对高质量query-chunk正样本
   - 为每个正样本构造3-5个负样本（相似query但不同chunk）
   - 特别关注那些query与chunk表达差异大的案例

2. **微调BGE-M3模型**
   - 使用上述训练数据对BGE-M3模型进行领域微调
   - 设置学习率2e-5，训练3个epoch
   - 增加对比学习损失，拉近正样本距离，推远负样本距离

3. **实施查询-文档双向编码**
   - 对查询和文档分别使用不同的编码策略
   - 查询编码：更关注问题类型词和条件词
   - 文档编码：更关注法律条款中的关键行为和条件描述
   - 预期提升：Dense独有5%的案例中可召回3-4%

## 4. RRF融合策略优化

**方案：自适应融合权重与排名迁移分析**

**具体步骤：**
1. **分析排名迁移模式**
   - 对RRF提升的63条案例进行深入分析，找出共同特征
   - 对RRF退化的35条案例进行归因分析
   - 建立迁移规则库，指导不同类型案例的融合策略

2. **实施动态RRF权重**
   - 根据查询特征动态调整k值和权重：
     - 当查询包含法律专业术语时，Dense权重提高，k值调整为70
     - 当查询为口语化表达时，BM25权重提高，k值调整为50
     - 一般情况使用当前k=60的RRF融合

3. **引入重排机制**
   - 对RRF融合后的top-20结果进行重排
   - 使用轻量级重排模型，考虑query与chunk的语义相似度和关键词匹配度
   - 预期提升：中位排名保持3的同时，均值排名从9提升至6-7

## 5. 完全丢失案例专项处理

**方案：构建法律问答匹配模型**

**具体步骤：**
1. **收集完全丢失案例**
   - 将8%的双路丢失案例作为重点研究对象
   - 扩展收集类似表达差异的案例，构建至少200个专项案例库

2. **训练专门匹配模型**
   - 使用上述案例训练一个轻量级法律问答匹配模型
   - 模型输入：query和chunk文本
   - 模型输出：匹配分数（0-1）
   - 模型架构：基于BERT的孪生网络，参数量控制在50M以内

3. **集成到检索流程**

   - 匹配模型对top-50 chunk进行评分，补充返回高分结果
